# MiniMax H3 local runtime

## Verified contract

Application → guarded HTTP gateway on 8191 → ComfyUI on loopback 8188. The gateway source and exact fixed graph are `ops/fasth3/fasth3_gateway.py` and `workflow_api.json`. Current runtime capabilities are v6; fetch `/v1/capabilities` to verify an installed instance rather than assuming the archived workstation v3/v4/v5 JSON is current.

| Parameter | Value |
| --- | --- |
| Video model | minimax_h3_fl2va_int8_convrot.safetensors (full INT8, not pruned) |
| Text encoder | qwen3vl_32b_minimax_h3_int8_convrot.safetensors |
| Video VAE | minimax_h3_video_vae_fp16.safetensors |
| Audio VAE | minimax_h3_audio_vae_fp32.safetensors |
| PDD | MiniMax-H3-FL2VA-Acc-8Step.safetensors |
| Sampler/steps/CFG | Euler / 8 / 1 |
| Sigma shift | video 12, audio 3; use PDD node's second output |
| Output | 1344×768, 24 fps, MP4 with generated audio |
| Duration | 5–15 s; align round(seconds × 24) upward to length % 17 == 5, max 345 frames |
| External LoRA / Motion Context | disabled |

T2VA is stateless. Controlled I2VA uses only the previous published segment's verified PNG tail as first_frame, with dimension/hash checks and the exact Picture 1 header. Target last_frame is forbidden. The server chooses conditioning and compiles node inputs, never an arbitrary model-authored path. Film-plan-v1 adds compiler-owned ordered Shot markers/cut times and dialogue blocks. The four prompt body fields remain summary, detailed_description, overall_soundscape, non_diegetic_music.

## Install ComfyUI and the required PDD node

The source baseline observed for this application is ComfyUI commit `10febb01d7be73d1491cf5e5347b5ab8b6c2c09e`, torch 2.13.0 and frontend package 1.51.9. The gateway advertises ComfyUI compatibility 0.34.0. Match a CUDA-enabled Torch wheel to your GPU/driver using the upstream project guidance; installing a CPU wheel cannot run H3.

```bash
sudo install -d -m 0755 /opt/comfyui-fasth3
sudo git clone https://github.com/Comfy-Org/ComfyUI.git /opt/comfyui-fasth3/ComfyUI
sudo git -C /opt/comfyui-fasth3/ComfyUI checkout 10febb01d7be73d1491cf5e5347b5ab8b6c2c09e
sudo python3 -m venv /opt/comfyui-fasth3/venv
# Install the CUDA-enabled torch 2.13.0 wheel appropriate to your driver first.
sudo /opt/comfyui-fasth3/venv/bin/pip install -r /opt/comfyui-fasth3/ComfyUI/requirements.txt
sudo git clone https://github.com/Jalen-Brunson/ComfyUI-MiniMax-H3-PDD-Acc.git \
  /opt/comfyui-fasth3/ComfyUI/custom_nodes/ComfyUI-MiniMax-H3-PDD-Acc
sudo git -C /opt/comfyui-fasth3/ComfyUI/custom_nodes/ComfyUI-MiniMax-H3-PDD-Acc \
  checkout c49484c0639c3d5a8b2def41306f7a631154d60f
# Install the custom node's requirements.txt if present.
```

Obtain the five exact model files above from their publishers. See [MiniMax H3](https://github.com/MiniMax-AI/MiniMax-H3) and the [PDD node/model instructions](https://github.com/Jalen-Brunson/ComfyUI-MiniMax-H3-PDD-Acc). Put the video model in `ComfyUI/models/diffusion_models/`, encoder in `models/text_encoders/`, both VAEs in `models/vae/` and PDD in `models/pdd_acc/`. Confirm filenames appear in `/object_info`; renamed incompatible weights will still fail at load time. Weights and access tokens are deliberately excluded.

```bash
sudo install -d /opt/comfyui-fasth3/gateway /opt/comfyui-fasth3/ComfyUI/input /opt/comfyui-fasth3/ComfyUI/output /opt/comfyui-fasth3/ComfyUI/user
sudo cp ops/fasth3/fasth3_gateway.py ops/fasth3/workflow_api.json /opt/comfyui-fasth3/gateway/
sudo cp ops/fasth3/extra_model_paths.yaml /opt/comfyui-fasth3/
sudo cp ops/fasth3/comfyui-fasth3.service ops/fasth3/crowdmovie-fasth3-gateway.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now comfyui-fasth3 crowdmovie-fasth3-gateway
curl -fsS http://127.0.0.1:8188/object_info > /tmp/crowdmovie-object-info.json
curl -fsS http://127.0.0.1:8191/v1/capabilities
```

These GPU service templates run as root for compatibility with GPU/system tooling; keep their listeners private and harden to a dedicated GPU account for your environment if appropriate. Do not run another ComfyUI process on the same port/GPU. The reserve-vram option is a reference tuning value, not a measured capacity guarantee.

## Gateway environment

The export defaults to a single private host. Set these in a systemd drop-in to split app/GPU hosts:

- FASTH3_GATEWAY_HOST / FASTH3_GATEWAY_PORT: bind interface / 8191.
- FASTH3_ALLOWED_CLIENTS: explicit comma-separated app client addresses (loopback by default).
- FASTH3_PUBLIC_BASE_URL: app-reachable private gateway URL; the name does not require an internet-facing endpoint.
- FASTH3_COMFY_URL: http://127.0.0.1:8188.
- FASTH3_WORKFLOW_PATH: /opt/comfyui-fasth3/gateway/workflow_api.json.
- FASTH3_OUTPUT_ROOT: /opt/comfyui-fasth3/ComfyUI/output.
- FASTH3_STATE_PATH: /var/lib/crowdmovie-fasth3/jobs.json.
- FASTH3_GENERATION_TIMEOUT_SECONDS: 1800.
- FASTH3_FILM_PLAN_ENABLED: true.

Use `python3 -m unittest discover -s ops/fasth3 -p 'test_*.py'` for offline contracts. Then use the director validation canary before real GPU work. Only after explicit generation authorization submit a bounded render and verify the returned job, downloaded digest, ffprobe media streams/duration and application publish state.

The thermal guard and power-limit units are optional hardware-specific helpers, not prerequisites; review GPU identity/limits before enabling. Motion Context and other old experimental workflow files are not needed for this v6 path.
